# Decisions
- [M0] Scaffolded with create-next-app (Next 16.4, React 19.3, Tailwind 4) in a temp dir and copied in, because the project folder was not empty.
- [M0] Disabled Next 16's `cacheComponents`/`partialPrefetching` defaults — the app is client-heavy and local; avoids GET handlers that read env being prerendered at build.
- [M0] @types/node bumped to ^24 to satisfy vitest 5 peer deps.
- [M0] shadcn initialised with the radix base (`radix-nova` style); components restyled to tokens in M1.
- [M0] Model client: openai SDK with maxRetries 0 and our own retry policy (one transient retry after 2s, one 400 → plain-JSON retry), plus a small circuit breaker (3 failures → mock for 60s).
- [M0] .env.local has MODEL_ID=muse-spark-1.3 (newer than plan's 1.1); used as-is.
- [M0] CLI scripts load .env.local with a tiny loader (scripts/load-env.ts) rather than adding dotenv.
- [M1] Theme via next-themes with `attribute="data-theme"` (matches the plan's `[data-theme='dark']` tokens); Tailwind `dark:` variant mapped to the same attribute.
- [M1] shadcn semantic vars (`--primary`, `--border`, …) are defined in terms of the §8 tokens, so restyling is central rather than per component. Added a `danger` button variant for Stop.
- [M1] Added derived tokens `--signal-ink` (amber text readable on paper) and `--flag-shadow` (the single on-screen shadow).
- [M1] Dev indicator disabled so screenshots stay clean.
- [M2] Renderers emit a pure "skeleton" (plain objects, no Excalidraw import) so they're unit-testable in Node; `lib/board/excalidraw.ts` converts on the client with `convertToExcalidrawElements({regenerateIds:false})`.
- [M2] Matrix placement: quadrant by score (4–5 = high half), then nearest free cell in a fixed 3×3 grid per quadrant — non-overlap is guaranteed by construction; overflow spills to the nearest free cell anywhere.
- [M2] Canvas/table rows grow to fit their stickies (row heights computed from item counts), so 12+ items never overlap.
- [M2] Structure elements (axes, block outlines, labels) are `locked` so the facilitator can't nudge the frame by accident; stickies are free.
- [M2] Board text uses Excalidraw's Helvetica (system font) for a clean consulting look; Excalidraw fonts are self-hosted via a postinstall copy to public/excalidraw-assets (offline demo).
- [M2] Library previews use `exportToSvg` rather than ten live Excalidraw canvases (much lighter).
- [M2] Sample script and canned fills live in lib/transcript/sampleScript.ts and lib/frameworks/sampleFills.ts; illustrative fills for the other seven frameworks are clearly marked as preview-only.
- [M3] Accept-on-edit compares a per-sticky signature (x, y, width, text) captured at placement instead of raw element versions — Excalidraw bumps versions itself when it re-measures text after fonts load, which would otherwise auto-accept everything.
- [M3] Acceptance is deferred until the gesture ends (drag/resize/text edit), then applied with CaptureUpdateAction.EVENTUALLY so undo groups it with the user's edit.
- [M3] Toolbar trimmed with CSS (`.ToolIcon:has([data-testid=toolbar-…])`) since Excalidraw 0.18 has no API to hide individual tools; style panel, main menu, library and help are hidden too. Excalidraw's own frame-name label is off (`frameRendering.name=false`) because the frame has an in-canvas title.
- [M3] Standalone `/board?fw=…` route (scratch session) powers "Open board" from /library; the same BoardPanel is embedded in the session console later.
- [M3] `window.__ciacBoardApi` exposes the Excalidraw API for Playwright tests (harmless debug hook).
- [M3] Re-fill merge implemented now (not M9): drops current provisional items, adds new ones nudged clear of existing stickies, skips duplicates of text already on the board, never touches accepted items.
- [M4] Zustand (vanilla store + context) for the console: sources, scheduler and board callbacks read/write state outside React render.
- [M4] Sample and paste share one `ReplaySource` (scripted timeline: interim word-by-word, then sentence finals). The session clock *is* the replay clock, so the 1×/1.5×/3× control also speeds up check pacing and elapsed time.
- [M4] Sample timeline honours the script's [mm:ss] anchors (compressing pace where a paragraph is long) so flags land near the marked points.
- [M4] Paste default speed 2× (≈300 wpm); "Process instantly" emits every final at once (brain scans windows over it in M5).
- [M4] A reloaded live session comes back paused; mic/replay resumes only on click. Replay resumes from the saved position.
- [M4] Start listening calls getUserMedia in the click handler (prompt appears right after the click), then navigates to the console which starts recognition. The start card shows the live level only if mic permission was already granted.
- [M4] Source cleanup is deferred a tick so React StrictMode's simulated unmount doesn't stop a running source.
- [M4] `typecheck` runs `next typegen` first so `PageProps<'/session/[id]'>` route types exist without a build.
- [M5] Mock engine: stemmed signal-phrase scoring (multi-word phrases weigh more), thresholds strong ≥ 4.5 / possible ≥ 2, plus "prefer" rules (build-buy-partner over options-appraisal, value-feasibility over impact-effort when close). Calibrated so the sample fires VF → stakeholder → BBP (unit test asserts order and timing).
- [M5] Fills use `reasoning_effort: "minimal"` (plan said medium): Muse Spark spent 3–6k reasoning tokens and 20–50s at low/medium; minimal keeps quality on the sample. Checks stay at "low".
- [M5] Fill calls are hedged: a second identical request goes out if the first hasn't answered after 10s; first success wins. 40s per-call cap, then mock (canned for the sample).
- [M5] Fill prompt now says to include every option the room named (score 3 when no view given) — the first prompt dropped half the sample's ideas.
- [M5] Model reasons are sanitised: first sentence only, 4–22 words, no repeated 3-word phrases — otherwise the framework's plain template reason is used (Muse Spark sometimes produced run-on/repeating reasons).
- [M5] Scheduler skips calling the model when an auto flag couldn't be shown anyway (inside the 2-minute gap), saving calls. Pacing memory is rebuilt from saved suggestions after reload.
- [M5] Pasted transcripts processed instantly are scanned in ~220-word steps (≤14 checks) on the virtual clock with the default pacing profile.
- [M5] ⌘K opens the board immediately (empty frame with ghost labels) and fills it from the transcript in place, rather than blocking on the fill.
- [M6] Opened flags move to the one-line "Earlier" list immediately (with "opened"), alongside flags untouched for 10 minutes, keeping the rail calm; clicking an Earlier item reopens its board.
- [M6] Fit label sits on its own line above the actions (matches §9.3 order and avoids overflow while "Preparing board… Ns" is shown).
- [M6] A flag is marked "seen" (clearing the pill's amber dot) when the facilitator hovers or focuses it.
- [M7] Sample detection for canned fills keys on "harbourline" plus any of several early phrases (newsletter, cancel their subscription…) — at 3× the first flag can fire before "cancellation model" is said, which fell back to extraction (4 items).
- [M7] Board Esc handler ignores `role=dialog` elements inside `.excalidraw` (its CSS-hidden style panel renders colour/font pickers as dialogs whenever something is selected, which blocked Esc).
- [M7] `npm run e2e` builds first and runs `next start` with MOCK_MODE=1 on port 3100 (deterministic, no API spend).
- [M7] Eval cases are scored on the live model; mock engine scores 5/10 on them (it's tuned for the sample + paste paths) — acceptable since mock is a fallback. `npm run eval -- --mock` shows it.
- [M7] No prompt changes needed: live eval scored 10/10 with zero false positives on the first run.
- [M8] One BroadcastChannel per session (`ciac-room-<id>`); the console is the source of truth and answers the room's `hello` with a full snapshot; on console load it sends `ping` so an already-open room re-syncs (avoids a hello/snapshot loop).
- [M8] Room viewport follows the facilitator's visible rectangle clipped to the board's bounds (+3%), so a zoomed-out console doesn't shrink the projector view, while zooming into a corner is still followed exactly.
- [M8] Room hides provisional AI items *and* ghost labels (reuses `acceptedOnly`). Send to room opens the room window if none is connected.
- [M8] B (blank) and J (captions, Room mode only) work over the board too — Excalidraw binds neither key. D toggles "dim room" inside the room window (plus a hover-revealed button).
- [M8] Room forces its own theme via a `data-theme` wrapper (light default), independent of the console's theme.
- [M8] Top-bar room status: "Open room view" until a room exists, then a menu button outlined green while a board is showing ("In the room"), with blank/captions/stop-showing items.
- [M9] Board switcher is a "Boards n" menu in the board header (only with ≥ 2 boards), marking the current board and the one in the room.
- [M9] Session summary (duration, words, suggestions, marked moments, boards) appears at the top of the rail once the session has ended; pure `summarise()` is unit-tested.
- [M9] Provisional bar never wraps: below 1360px viewport it shortens to "Clear" / "Re-fill" (aria-labels keep the full names).
- [M9] Sticky font size left as-is (16px): bigger text would make Excalidraw grow sticky heights and break the guaranteed non-overlap; the room view instead zooms to the board's bounds.
- [M9] Packing, re-fill merge, ghost labels and reduced motion were already done in M2/M3/M6; checked, no changes needed.
- [M10] Share link and PNG carry kept (accepted) items only — AI suggestions stay private, same rule as the room; the .excalidraw download is the full working board.
- [M10] Share links drop fields Excalidraw restores itself (versionNonce, seed, index…) and slim customData; a matrix board is ~6k chars of URL, fine for Chrome. `/view` stores nothing.
- [M10] Session notes group kept items under their quadrant/block/cell labels (read from the board's own label elements), list facilitator-drawn items under "Other notes", count unreviewed AI suggestions, and list marked moments. Available from the board's Share menu and the end-of-session summary.
- [M10] Radix dropdown occasionally ignores a click immediately after a previous item's async action in headless tests; e2e reopens with a retry. Not seen as a user-facing issue.
- [M11] Custom frameworks: pure `buildCustomFramework` turns the form into a zod-validated template (`custom-<slug>` ids, never clashing with built-ins); canvas blocks auto-grid (2 columns up to 4 blocks, else 3). Plumbing to checks/⌘K/chips/fill already used `getAllFrameworks()`, so no brain changes were needed.
- [M11] Import accepts an export bundle, an array, or a single template; imported ids equal to a built-in are prefixed `custom-`; same id replaces (so re-importing updates).
- [M11] Form validation messages use ink, not red (red is reserved for Stop/delete per §8.1).
- [M11] Verified live: Muse Spark picked a custom "Risk heat map" as a strong fit (4s) and filled it with sensible likelihood/severity scores (20s) — `scripts/try-custom.ts`.
- [M12] Error boundaries per Next 16 docs: `app/error.tsx` (props `error`, `retry`), `app/global-error.tsx`, and a board-level `catchError` boundary so a whiteboard crash leaves the transcript, flags and listening running.
- [M12] Long-session check: a seeded 1,600-segment (~2 h) transcript renders in well under a second and shows 0 long tasks over 15 s of streaming (`qa/tools/perf-long.mjs`), so no virtualisation was added (paragraphs already use `content-visibility: auto`).
- [M12] Accessibility: axe-core (dev dependency, `qa/tools/a11y.mjs`) clean on start, library, console, board and room in both themes after two fixes — role on the mic level box, and dark-mode Stop text uses a new `--danger-ink` token (white on #F0675D was 3.1:1).
- [M12] Instant-processed pastes use a new `scan` pacing profile (no gap between flags, each framework once) — the live 2-minute gap on the virtual clock hid all but one flag, which undermined the 30-second fallback demo.
- [M12] Session summary sits below active flags in the rail (flags needing attention come first).
- [M13] Meeting bot provider: Vexa (Apache-2.0, Google Meet listed production-ready, REST polling so no webhook/tunnel; hosted $2 free credit ≈ 6 bot-hours at ~$0.30/h, or free self-hosted). Recall.ai (~$0.50/h + $0.15/h transcription, account + webhooks) and Attendee (Meet support unclear in README) documented as alternatives in MEET_BOT_SETUP.md.
- [M13] Added a `mock` bot provider that replays the sample as a fake call (in server memory), so the whole bot path is e2e-tested without an account; `MEET_BOT_PROVIDER` auto-selects vexa when `VEXA_API_KEY` is set.
- [M13] Bot transcript is polled every 2 s; completed segments become finals exactly once (pure `diffSegments`, unit-tested), incomplete ones show as interim; speaker change or 2 s gap starts a paragraph. Bot sessions use the default (live) pacing profile.
- [M13] Isolation: everything gated by ENABLE_MEET_BOT=1 (start-card field hidden, /api/bot → 404); e2e asserts both the off and on behaviour (second test server on :3101).
